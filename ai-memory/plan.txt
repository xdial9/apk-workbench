## PROGRAM IDENTITY (top of file; read first every session)
The program is a STATIC, deterministic, no-thought read/write DATAMAP engine.
Its value chain ends at the AI WORK ASSIGNMENT (the handoff): the briefs,
facts, deduped findings, coverage gaps and playbooks that the terminal AI
call consumes. THE IDENTITY HIERARCHY:
  1. The pipeline's whole purpose is to produce a complete, deduplicated,
     evidence-cited datamap of every artifact + the work order that turns it
     into intelligence.
  2. The terminal AI is the ANALYST, not a reader: its mandated workflow is
     (a) FIRST read and map the entire RAW DECOMPILed .apk tree itself —
     independent observation BEFORE seeing tool conclusions (anti-anchoring:
     own findings recorded in ai_analysis BEFORE cross-checking the tool's
     static-analysis); (b) THEN read the program output (facts, findings,
     coverage ledger, playbook); (c) TRACE EACH HINT — pursue, decode,
     correlate, and make the judgement findings/deductions a static tool
     cannot make; (d) finish the coverage; (e) write the final dossier +
     overlay into ai_analysis/ with citations.
  3. Every stage before the handoff therefore exists to maximize the
     handoff's quality: exhaustiveness of extraction, dedup cleanliness,
     evidence citability, honest coverage gaps, and an ao playbook worth
     executing. A stage that does not improve the handoff is dead weight.

## 1. DOCTRINE (standing rules for every change)
- Linear, sequential, slow, accurate. Low hardware. "Turn on, go to sleep."
- DEDUCE FROM DATA, NEVER GUESS: tool flags verified against installed binary;
  analyzer deductions cite file:line evidence; corpus links only on exact
  fingerprint matches (similarity = labeled hint, never a link).
- No maximums, no timeouts: if it works, it runs to completion.
- Findings must NEVER be redacted/hidden/unsearched; classify all knowledge by
  confidence (verified / deduced / hint).
- Tools point at the ORIGINAL .apk; derived artifacts only when a tool cannot
  read the format directly (Appendix C exception clause).

## 2. PHASE LADDER (order)

### PHASE A — Remove ceilings (maxima/timeouts -> none)
- apk_surface: kill 8MB/file + 512MB total budgets, 100k findings cap.
- androguard_dex: kill 64MB out / 100k methods / 200k edges / 100k strings
  caps + 1800s timeout (keep heartbeats).
- decompilation/runner: remove 3600s timeout (SIGINT cleanup stays).
- trufflehog.py: remove 2h timeout + 512MB out cap.
- executor/contracts: knobs default null-unbounded.
- config.py: timeout/limit keys ignored by default; operator override knob
  exists but never set by default.
- doctor: drop timeout expectations.

### PHASE B — Capture every hint + tool maximization
1. TruffleHog (flags verified from installed 3.99.8 help):
   - PRIMARY verified-only scan (minimal, justified):
     `filesystem --concurrency=1 --no-update --results=verified --json --fail-on-scan-errors <dir>`
   - hard-abort on unverified/malformed lines RETAINED (defective output can't
     be deduced from).
   - HINT PASS (second scan):
     `filesystem --concurrency=1 --no-update --results=verified,unverified,unknown --json --filter-unverified --no-ignore-tag --fail-on-scan-errors <dir>`
     stored as hints: verified=tool_verified, unverified=corroborated_static,
     unknown=flagged_error. --filter-unverified dedupes; --no-ignore-tag
     re-hydrates tag-suppressed lines (hidden-findings class we opt out of).
   - Default detector set is already ALL; --allow-verification-overlap NOT used.
2. Reports (per-APK + final) render verified AND hint buckets w/ labels.
3. Asset packs (.pak etc.) acquired, hashed, manifested, analyzed.
4. Surface output becomes first-class report content (not stage counts).

### PHASE C — Surface analyzer full rewrite (deducing engine)
On the dormant framework (contracts/registry/executor, database/evidence.py):
1. Parsers -> facts (dedup by value fingerprint): manifest, every smali file,
   resources, assets, so files, DEX (Androguard), asset packs, zip inventory.
2. Deduction rules -> estimated logics with confidence + cited evidence
   (beaconing, SDK reconstruction, obfuscation detection, crypto graphs).
3. Coverage ledger per file -> explicit "not analyzed: X" (should shrink to
   dynamic-only items).
4. Wire analyzer registry/executor in for surface analyzers; SQLite as
   shadow store; CSVs stay source of truth until proven equivalent.

### PHASE D — Dossier generator
Per app Markdown + JSON: Identity/provenance, Architecture map, Network life,
Security posture, Secrets (verified+hints), Deduced behaviors, Relationship
graph, Unknowns/exclusions. Every deduction evidence-clickable (file+line+hash).

### PHASE E — Corpus correlation (SQLite finding_relationship)
same_endpoint / same_vendor / duplicate_value / derived_from / conflicts;
fingerprint-match links only; similarity = hint. Query surface for cross-app
questions; additive phase.

## 5. APPENDIX C — Input policy: original .apk
Every tool's primary input = the original APK. Only exception: a tool that
cannot read a format directly takes the earliest derived artifact that unlocks
that content (e.g. trufflehog needs decoded smali; surface text sweep needs
decode trees; androguard MUST keep reading the original APK — hash-guarded).
Surface must build a complete zip-member inventory (every member listed +
hashed) so undecoded members are still mapped. Tests:
- trufflehog scan set == decode tree + original-only members.
- surface facts include full zip member inventory with member hashes.
- androguard input hash == original APK hash on every execution.

## 7. APPENDIX D — ALWAYS-ALIVE TERMINAL (standing rule, all stages)
At NO time may the terminal screen be blank or frozen. The user must be able
to tell instantly whether the program is working or hung, on ordinary low-
hardware terminals (plain STDOUT/TTY, no rich-TUI dependency).

Requirements for EVERY stage and sub-stage (surface analyzer included):
- A continuously refreshing line that proves forward motion: at minimum a
  counter/percentage for closed-form work (X/Y files, Z/N artifacts, G.OF.T
  bytes) and, for open-ended work, a unitless status that changes on every
  processed unit (latest file, current rule, chunk number).
- A one-line description of the CURRENT work item (e.g. "scanning resources/
  strings.xml rules 12/19", "hashing base.apk chunk 1024").
- Max normal-emit interval: nothing silent longer than ~2s of wall clock
  during active stages; heartbeats (e.g. elapsed: N s) when a single unit
  takes longer than that.
- Long single-unit operations (DEX analysis, huge file sweep, hash of a large
  APK)must emit sub-unit progress (chunks, methods, edges) not just stage
  labels.
- Existing progress hooks in this direction exist and MUST be kept/widened:
  _emit_progress in google_play.py / apk_surface.py, androguard per-second
  heartbeats, trufflehog findings-counter, decompilation live log tail.
- CI/tests: fake clocks and long ops must assert the emit interval contract
  (non-silent > 2s is a test failure).
Mechanism note: implement parity across stages via a tiny shared progress
printer (replaces copy-paste _emit_progress variants progressively; unchanged
semantics: single line updates via \r, no flicker, no blank lines).

## 8. PHASE D AMENDMENT — AI HANDOFF (decided 2026-11-14)
A. AI as last stage (manual, not automated): acceptable and designed for.
   The tool produces the deterministic evidence; an external AI session works
   as the terminal reasoning stage per artifact. AI outputs must be labeled
   ai_deduced and never silently merge with tool_verified findings.
B. Token-efficiency data-plane rules (apply from Phase S onward):
   - Facts deduped by fingerprint; multi-occurrence values carry ONE entry
     with representative evidence, never N copies (tokens are a cost).
   - Dense deterministic shapes (JSON/JSONL, one shape per app); snippets
     size-capped; exact file:line pointers (pull context, don't push it).
   - Graded briefing: established facts -> verified findings -> hints ->
     what nobody checked (coverage ledger verbatim).
C. Per-run/per-APK handoff folders:
   - Content layer stays GLOBAL (downloads/, results/, ledgers, sha256
     dedup across runs - immutable history keeps deduplication).
   - At end of `run`, materialize handoff/<run_id>/<pkg>/<ver>/<digest>/
     containing: BRIEFING.md (written for a model with zero project memory),
     dossier/brief data, static-analysis.json, trufflehog verified+hint
     findings, the artifact's verification rows, decode tree, and the
     ORIGINAL APK - assembled with HARDLINKS (no symlinks; zero disk copy).
   - One folder = one APK = complete, cold-start consumable; user hands the
     AI any folder, one at a time; 100 runs = 100 ready folders.
   - "Independent to consume, shared underneath": dedup stays global, the
     view is self-contained.
D. Optional feedback loop: AI conclusions can return as a machine-readable
   overlay (ai_analysis_<run>.json, verification_state=ai_deduced, evidence
   links to the same trails); corpus untouched; additive and diffable.
E. Format rule: briefing/dossier maximally useful to a human with a text
   editor AND to any future AI; never require any specific model to read.
D2. MODEL-AGNOSTRIC HANDOFF LAW (added 2026-11-14; binding from Phase S1
   serialization design onward): every pipeline output EXCEPT trufflehog
   VERIFIED findings must be authored for the final AI tool call and remain
   consumable by virtually any capable model: self-describing schemas,
   plain formats (JSON/JSONL/Markdown), inline terminology definitions in
   the briefing, no external-context references, machine-verifiable
   evidence chains, stable invariants (same key = same meaning in every
   artifact/run), paging-friendly structure (briefing indexes everything;
   no single load-bearing file), no reliance on model memory/tools/keys
   the reader does not have.
D3. ACTIVE-AGENT HANDOFF (user directive 2026-11-14; pillar P10 of
   surface-plan-v2; §7A there holds the full design): the AI is NOT a
   read-only reporter. Every handoff grants direction (ranked open leads +
   location ledger + suggested methods as goals, not commands), a
   permission map (immutable evidence vs writable ai_analysis/ overlay),
   and a defined finish line (all coverage triaged, leads pursued or
   dismissed with reasons, overlay + narrative written with citations) so
   the final tool call actively extends the analysis and closes the
   process ("sews it up neatly"). Capability-adaptive: with or without
   shell access, any capable model can execute the loop.
   F. RUN WORKSPACE ISOLATION (amends C; decided 2026-11-14):
      - Downloads stay in the UNIVERSAL content folder (dedup by sha256
        unchanged; never moved/duplicated by runs).
      - ALL outputs of one run live in ONE per-run folder:
        workspace/runs/<run_id>/ - the frozen manifest copy, phase-one
        verification report, static-analysis.json + trufflehog outputs per
        artifact (hardlinked from the digest-keyed work cache when bytes
        are identical), markers, dossier/briefing, handoff files.
      - Universal tree becomes the work cache (pure function of APK bytes;
        cross-run skip-reuse reads it); run folder = the RECORD and the AI
        consumption unit: self-sufficient with no external references,
        including a hardlink of the original APK.
      - The AI is pointed at workspace/runs/<run_id>/ (or any single artifact
        subfolder within it) with zero project context and finds everything.
      - Phase C adopts the run-folder layout natively (one migration during
        the full rewrite; Phase S keeps current paths to stay green).
